# AUDIT-09 실행 제한 일치 — 로컬 구현, 미배포

- 기존: 밀리초를 정수 초로 올림. 생성/제출에 실행기 수용 범위 검증이 없어 정상 접수가 나중에 인프라 실패가 될 수 있었음.
- 변경: 생성 전, 일반/대회 제출 저장 전, 큐 발행 전에 같은 실행 계약 검증. 1000~30000 ms의 1000 배수만 허용하며 자동 반올림/기존 데이터 변경 없음.
- 메모리 16~1024 MiB, 테스트 1~100개, 총 실행 예산 20 + N*(시간초+2) <= 600초.
- 코드/각 입력/각 정답 UTF-8 1 MiB, base64 입력 묶음 16 MiB(최대 코드와 헤더 여유 포함). 허용 언어 python/c/cpp.
- 기존 범위 밖 문제는 제출 전에 400으로 거부. 운영 DB 읽기 검사 및 출제자 수정이 배포 전 조건. 실제 DB는 변경하지 않음.
- 메모리는 현재 주소 공간 제한(RLIMIT_AS). RSS와 동일하지 않으며 전체 디스크 사용량 강제 제한과 Fargate 실측은 아직 미해결.
- 실행안: 기존 문제 설정/테스트 크기 점검 → 백엔드 테스트 및 runner 계약 대조 → 승인 후 백엔드만 교체. DB 스키마 변경 없음.
- 복구: 직전 백엔드 이미지로 복귀. 잘못된 제한을 허용하던 동작도 복귀하므로 제출을 제한하고 원인 확인.
- 로컬 검증: 경계/UTF-8/전체 예산/입력 누락 테스트와 제출 부작용 차단 회귀. 실제 Fargate, DB, 배포는 별도 승인 대상.
